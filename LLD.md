# SkillSwap - Low Level Design (LLD)

## 1. Frontend Component Architecture

The frontend is built using React with Vite. Navigation is fully URL-driven via React Router (`react-router-dom`).

### Core Components
- **`App.tsx` & `index.tsx`:** Provide the application context, wrap the app in `<BrowserRouter>`, and initialize Firebase configuration.
- **`MainApp.tsx`:** The root structural component handling the `<Routes>` switch and managing global state (Firebase auth state, Realtime presence, user profile object).
- **`components/Sidebar.tsx`:** Left-hand navigation utilizing `useNavigate` and `useLocation` to route users between major views.
- **`components/Dashboard.tsx`:** The landing page for authenticated users showing active sessions, incoming swap requests, and XP history (using Recharts).
- **`components/Matching.tsx`:** The core discovery engine, sorting users algorithmically based on shared Strong/Weak skills.
- **`components/SessionModule.tsx`:** The real-time workspace collaboration module. It handles Gemini Roadmap generation, Gemini Quiz execution, and contains the ChatDrawer workspace.
- **`components/LoginModal.tsx`:** Handles profile setup, onboarding, and updating the user's strong and weak skills.

### React Router Mapping
- `/dashboard` -> `<Dashboard />`
- `/matches` -> `<Matching />` (Explore Hub)
- `/learn` -> `<LearnHub />`
- `/sessions` -> `<History />` (Placeholder Ethereal History view)
- `/leaderboard` -> `<Leaderboard />`
- `/marketplace` -> `<Marketplace />`
- `/assistant` -> `<AIAssistant />`
- `/workspace` -> `<SessionModule />`
- `/profile` -> `<LoginModal />` (Rendered over the dashboard)

## 2. Backend API Architecture (Express)

The backend is a Node.js Express server (`server/index.js`).

### Middleware Pipeline
1. **CORS:** The `cors` package handles dynamic origins (`http://localhost:3000`, `http://localhost:5173`, `https://skillswap-grow.netlify.app`).
2. **Rate Limiting:** `express-rate-limit` enforces limits (`limiter` for general API endpoints, `aiLimiter` strictly for Gemini AI endpoints).
3. **JSON Parsing:** Standard `express.json()`.
4. **Authentication (`verifyToken`):** Intercepts requests, extracts the Firebase Bearer token, and verifies it against Firebase Admin SDK (`firebase-admin`).

### Security & Sanitization
All incoming request payloads are validated using **Zod**. If validation passes, string inputs are scrubbed of malicious tags via the `sanitize-html` library before hitting business logic or the database. AI prompts are secured via `buildSafePrompt(instruction, userInput)` to prevent prompt injections.

### Express API Endpoints
- `GET /api/leaderboard`: Fetches the global XP ranking from Postgres.
- `GET /api/swap-requests`: Fetches pending requests for the authenticated user.
- `POST /api/swap-requests`: Creates a new connection request.
- `PATCH /api/swap-requests/:id`: Accepts or rejects a swap request. (Accepting automatically generates a Session).
- `GET /api/sessions`: Fetches scheduled and completed sessions.
- `POST /api/sessions/complete`: Finishes a session, awards XP, and writes a review.
- `POST /api/chat`, `POST /api/quiz`, `POST /api/roadmap`: Secure Gemini AI wrappers for content generation.

## 3. Database Schema (Prisma)

Data is strictly typed and related through Prisma to PostgreSQL.

### Prisma Models
- **`User`**: Core profile data synced from Firebase.
  - Fields: `id`, `firebaseUid`, `email`, `totalXp`.
- **`SwapRequest`**: Connection requests between a sender and receiver.
  - Fields: `id`, `senderUid`, `receiverUid`, `skillOffered`, `skillWanted`, `status` (PENDING, ACCEPTED, REJECTED).
- **`Session`**: Active or past collaborative workspaces.
  - Fields: `id`, `tutorUid`, `learnerUid`, `status` (SCHEDULED, COMPLETED, CANCELLED).
- **`Review`**: Feedback loops appended after session completion.
  - Fields: `id`, `sessionId`, `rating`, `comment`.

### Prisma Transaction Workflow
When a session concludes, the database performs multiple atomic writes. If any step fails, the entire block rolls back to prevent data corruption.
```typescript
await prisma.$transaction([
  prisma.session.update({ where: { id: sessionId }, data: { status: 'COMPLETED' } }),
  prisma.review.create({ data: { sessionId, rating, comment } }),
  prisma.user.update({ where: { firebaseUid }, data: { totalXp: { increment: xpEarned } } })
]);
```

## 4. Chat & Real-Time Sync Structure
- **Presence:** `Realtime Database` stores active connections under `/status/{uid}`.
- **Chat:** `Cloud Firestore` stores messages under `/chats/{chatId}/messages`. The `chatId` is deterministically generated by sorting and combining the two users' UIDs (`chatId = uidA < uidB ? uidA_uidB : uidB_uidA`), ensuring both users query the exact same document.

## 5. Testing Strategy
- **Unit Tests (`tests/unit/utils.test.js`):** Tests Zod schemas, HTML sanitization, and Prompt-Injection builder functions as pure logic.
- **Integration Tests (`tests/integration/api.test.js`):** Uses **Supertest** bound to the exported Express `app`. Tests the authentication middleware (`401` on invalid token) and validation middleware (`400` on bad payload) without needing to boot a port.
